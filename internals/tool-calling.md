# 工具调用

工具的唯一注册来源是 `plugins/*/SKILL.md`。技能目录中的 `SKILL.md` 只影响提示词，即使带有工具 Schema 也不会成为 Provider function call。

## 发现到执行

```text
扫描 plugins/*/SKILL.md
  → 解析一级标题、描述和 ## Tool JSON
  → 校验名称、Schema、版本、开关和入口路径
  → 按用户 plugins.whitelist 过滤
  → ToolRegistry.schemas() 暴露给 Provider
  → 校验模型提交的 arguments
  → 执行 file.py:function
  → 把结构化结果写回模型循环
```

## 运行保护

| 机制 | 当前默认 | 作用 |
|---|---:|---|
| 单工具默认超时 | 240 秒 | 未显式提供有效 `timeout` 时防止工具无限阻塞 |
| 最大迭代 | 80 | 限制一次 Run 的模型/工具循环 |
| 连续相同签名 | 8 次 | 阻止工具名与参数完全相同的循环 |
| 连续失败阈值 | 5 次 | 本轮临时移除持续失败的工具 |
| 结果大小上限 | 20,000 字符 | 单次工具内联 JSON 结果超限时丢弃完整正文，只返回诊断 |
| 取消信号 | — | 请求取消后不继续后续工具 |

引擎只缓存一次 Run 中已经成功执行的相同调用签名，从而复用结果并避免重复副作用。失败、取消或超时结果不会进入成功缓存，模型修正参数或等待瞬时故障恢复后仍可重新调用。工具或参数变化会形成新的签名。

结果大小上限（v0.9.3 起）：主对话、子代理和任务计划统一对单次工具内联 JSON 结果施加 20,000 字符硬限制。超限时完整正文被丢弃，不会进入 Provider 输入、运行事件或历史，只返回 `ToolResultTooLargeError`、原始字符数与缩小范围的提示；这类受控拒绝不计入连续工具失败。读取大文件时应先用 `file.stat` 查看大小，再用 `file.read_range` 的 `start_line`/`end_line` 或 `tail` 分段读取，而不是直接 `read` 全文。

普通插件默认使用 `argument_or_default` 超时策略：工具 Schema 声明 `timeout` 且模型显式提供有效正数时，该值同时作为插件可见期限和框架外层看门狗；没有提供时使用 `tools.timeout`。专门调度子代理的工具使用 `agent_runtime` 策略，以子代理整体期限为准，不会被普通工具默认超时提前截断。

请求取消或工具超时时，运行时会向当前工具发送专属取消信号并留出短暂清理时间。该信号只针对本次工具调用，不会把工具超时误当成整轮用户取消；插件仍应主动检查取消信号并及时释放文件、网络或子进程资源。

## 文件编辑保护

内置 `file` 工具读取时返回带 1-based 行号的 `lines`，完整读取还返回文件 `sha256`。行替换和整行删除必须提交最近读取到的 `expected_old_text`；插入必须提交完整文件 `expected_hash`。文件在读后变化、Tab/空格不一致或目标行偏移时会拒绝写入，要求重新读取。

删除整行使用 `delete_line` 或 `delete_range`，不能用空 `replace_range` 猜测语义。编辑默认创建不覆盖的 `.bak`、`.bak.1` 等编号备份，并返回编辑前后哈希与目标附近预览；换行符、BOM 和文件末尾换行保持原样。

## 工具上下文

运行时只注入 `root`、`user`、`source`、`session_id`、`window`、`tool_timeout` 和授权策略等必要字段，不把主对话历史作为隐式参数下发。

::: danger 副作用
插件作者应让返回值明确反映成功或失败，并设计幂等或可核对的操作。运行时保护不能替代插件自身的事务与安全边界。
:::
