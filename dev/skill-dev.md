# 技能开发

技能是注入 system prompt 的 Markdown 指令，不注册 Provider 可执行函数。它适合承载工作方法、领域规范和可重复流程。

## 作用域

| 作用域 | 路径 | 可用范围 |
|---|---|---|
| 共享 | `shared_skills/<name>/` | 被主配置允许的所有用户 |
| 用户 | `users/<user>/user_skills/` | 当前用户 |

一个技能唯一必需文件是 `SKILL.md`，其余内部结构完全开放。可附带 `references/`、`scripts/`、`assets/`、模板、示例项目或其他任意目录；这些名称只是常见约定，不是允许列表。只有 `SKILL.md` 会被自动发现，其他资源必须由说明明确引导智能体按需读取或执行。

## 基本写法

```markdown
# code-review

审查代码正确性和可维护性的工作流程。

## 使用原则

- 先读取目标和相邻代码。
- 优先报告可复现问题。

## 操作流程

1. 确认修改范围。
2. 检查行为、错误处理和测试。
3. 按严重程度输出结论。
```

技能可以带 `## Tool` JSON 作为参数文档，但这只影响提示词，不会产生可执行工具。真正需要 function call 时应开发插件。

## 选择标准

- 只需要告诉模型“怎样做”：技能。
- 需要运行 Python、访问文件或外部服务：插件。
- 需要独立模型调用和隔离授权：子代理。

主智能体通过 `skills.shared_whitelist` 过滤共享技能；用户技能按当前用户目录发现。

## 从 Web 上传用户技能

技能页只接受 ZIP 压缩包，并且只能安装到当前用户的 `users/<user>/user_skills/user_create/`。服务会递归、大小写不敏感地查找 `SKILL.md`；每个最外层清单所在目录作为一项技能，技能目录内的脚本、资源、子目录和完整相对结构会一起保留。若其子目录还有清单，它会作为父技能的内部资源保留，不会重复安装为第二项技能。压缩包可以只包含一个技能，也可以包含多个彼此独立的技能。

上传采用暂存目录和事务提交：全部技能完成解压、结构校验和注册验证后才会一起进入用户目录。任意一项失败时整包回滚，不留下半安装状态；现有同名技能不会被覆盖。

服务会拒绝以下压缩包：

- 非 ZIP、加密 ZIP、损坏归档或没有 `SKILL.md`；
- 绝对路径、`..` 路径穿越、符号链接及其他特殊文件；
- 大小写冲突、同名安装目标或目标目录已存在；
- 超过归档大小、解压总量、文件数量、技能数量或压缩比限制；
- 把 `SKILL.md` 放入隐藏目录，或安装后无法被技能注册器发现。

这套校验只约束安装边界，不限制技能内部的创造自由。技能仍可携带完整项目、任意层级模块和自定义资源；需要执行代码时，`SKILL.md` 应明确说明入口、依赖和安全前提。
