# 定时任务

定时任务让智能体在未来自动执行一次或周期性工作。你可以直接用自然语言描述时间，系统会先把它解析成结构化的调度规则，再让你确认创建。

## 调度类型

| 类型 | 用途 |
|---|---|
| 单次 | 在某个确定时间执行一次 |
| 每天 | 每天在指定时刻执行，可以配多个时刻 |
| 每周 | 在指定星期执行，例如每周一、三、五 |
| 每月 | 在指定日期执行，例如每月 1 号、15 号 |
| 间隔 | 按固定间隔重复，最短 60 秒 |

「工作日」可以直接说，表示周一至周五。每月任务遇到当月不存在的日期（29、30、31 日）时会跳过，不会挤到月末。

## 生效区间与次数上限

- 可以给重复任务设置**开始日期**和**结束日期**，首尾都包含；
- 可以用**成功次数上限**约束总共执行多少次。

到达结束日期、没有下一次合法时刻，或达到次数上限后，任务会自动结束。

## 任务状态

| 状态 | 含义 |
|---|---|
| 等待调度 | 正常运行中 |
| 暂停 | 你手动暂停 |
| 执行中 | 正在运行 |
| 已完成 | 单次任务完成，或达到结束条件 |
| 失败 | 最近一次执行失败，**不会自动重试**，需要你重新启用 |
| 已取消 | 已终止 |

一次失败后任务不会无限重跑。这样既能避免反复触发副作用，也不会让异常记录刷满任务页。

## 执行历史

网页「任务」页把 **任务计划**、**定时任务** 和 **执行记录** 分成三栏：

- 定时任务按下次运行时间由近到远排列；
- 执行记录按最近执行时间由新到旧排列；
- 选中一条任务后，右侧展示调度规则、生效区间、成功次数与最近 / 下次运行时间。

执行记录读取的是真实的逐次结果，删除任务定义不会删除它的历史记录。系统维护类任务不会出现在你的任务页。

## 数量上限

每个用户最多保存 100 个定时任务；到达上限后，请先清理不再需要的定义。

## 提示词的写法

任务的提示词是自包含的——它在未来执行，看不到你创建它时的那段对话。所以请写清楚目标、数据来源、输出去向，以及失败时的行为。涉及对外发送时，要说明平台和目标身份，不要写「发给他」这类模糊表述。

::: warning 后台宿主
使用 `start_web.py --no-host` 时不会启动后台宿主，定时任务与消息路由都不会被托管。需要定时任务时请正常启动 Web 服务。
:::
