# 对话与历史

kemo-agent 把用户可见的完整归档与提供给模型的临时上下文分开保存，因此长时间使用不会要求每次都加载全部对话。

历史会话列表通过轻量索引和归档文件指纹定位会话。正常情况下只进行目录和文件元数据检查，不反复解析每个大型 `data.json`；索引缺失、损坏或检测到外部变化时才扫描完整归档并自动重建。

## 会话隔离

每次请求由 `user`、`source` 和 `session_id` 三者确定。相同用户可共享记忆和知识，但不同来源或会话的聊天上下文彼此隔离。

## 双层历史

| 层 | 位置 | 特点 |
|---|---|---|
| 完整归档 | `users/<user>/history/<window>/` | 无上限保存已提交的原始轮次 |
| Provider 工作区 | `users/<user>/history/temp/<window>/` | 受 `agents.max_rounds` 和 Token 预算限制 |

上下文只按完整轮次选择，不会拆开一次 user/assistant/工具调用消息组。较旧轮次可由摘要接力，摘要缓存在临时工作区中；摘要失败不会覆盖已有缓存，手动压缩落盘校验失败时还会恢复压缩前的工作区和摘要。

归档、临时工作区、摘要缓存和会话索引采用同目录临时文件加原子替换。Windows 上遇到安全软件或索引器造成的短暂共享冲突时会有限重试；持续权限错误仍会明确返回，不会静默跳过历史提交。

## 历史内容

每轮包含可见文本、思考记录、工具调用，以及统一的结构化 items。归档保留原始记录；临时工作区中的旧工具和思考日志可以被压缩。

::: tip 终态与记忆
正常完成、用户紧急停止、工具循环保护停止和 Provider 失败都会形成可辨认的终态轮次，避免长任务进度在下一轮前消失。只有成功轮次进入后续记忆提取；临时记忆加权必须由历史整理流程依据可回溯的用户原文命中，Prompt 注入、查看和搜索均不加权。`cancelled` 与 `failed` 轮次只保存对话现场，不会制造长期记忆。
:::

Provider 鉴权失败、限流、上游中断、拥塞、事件流缺少终态或上下文恢复失败时，历史中会写入统一中断标记和经过过滤的错误分类，不持久化完整上游响应体。下一条消息会作为新一轮继续，而不是覆盖或删除失败轮次。

## 历史卡片摘要

点击“保存并创建新对话”后，旧会话会立即关闭，标题与摘要则进入持久后台任务。该任务不占用当前 Web 请求线程；只要 RuntimeHost 仍在运行，即使关闭浏览器页面也会继续处理。

生成失败后会按配置自动退避重试，默认最多尝试 5 次。长会话按估算 Token 分块，并会把超大的单轮正文继续拆分；断点让进程重启或中途失败后从最近成功位置继续。

摘要优先要求模型通过结构化输出工具提交。模型仍返回普通文本时，运行时会依次尝试标准 JSON、Python 字典字面量和“标题/摘要”标签恢复；再次失败则使用已完成断点或当前用户输入生成安全的本地兜底摘要。因此卡片摘要不再把模型偶发的格式偏差直接扩大为长期失败。摘要仍是可重建缓存，不会替代或损坏完整归档。

历史卡片只显示单行摘要。鼠标悬停摘要小字或用键盘聚焦卡片时，会在页面顶层显示完整摘要；滚动列表、切换搜索或关闭抽屉后悬浮层自动消失。

## 历史正文搜索

主智能体的 `history_search` 工具检索完整归档中的用户与助手正文，不只检索卡片标题和摘要。它支持角色、普通子串、完整词、精确文本、正则表达式和相邻消息上下文。

时间筛选使用归档 `data.json` 的 `created_at` 转换为北京时间日期，同时兼容旧式带日期目录。新式 `conv_<uuid>` 目录不包含日期，也能正确参与筛选和按更新时间排序。
