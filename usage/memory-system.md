# 潮汐记忆系统

潮汐记忆不把全部聊天永久堆积为记忆，而是根据用户对话历史中可回溯的原文命中累积权重，并按七天、一个月、半年、永久四档流动。

## 四档生命周期

| 档位 | 有效期 | 晋级阈值 | 下一档 |
|---|---:|---:|---|
| `seven_days` | 7 天 | 3 | `one_month` |
| `one_month` | 30 天 | 10 | `half_year` |
| `half_year` | 180 天 | 60 | `permanent` |
| `permanent` | 永久 | — | — |

到期时，达到阈值的内容进入下一档并从 0 重新累计；未达阈值的内容会删除，而不是降级保留。

## 权重怎样增加

临时记忆只在保存、手动压缩、Token 超限压缩等历史整理中，被自我改进流程依据用户原文命中时加权。每条候选都必须能回溯到用户原话；助手回复、推理和工具结果不参与提取。同一记忆在同一自然日最多 `+1`。Prompt 注入、用户查看、工具搜索、失败或取消都不加权。

## 存储和控制

从 `v0.10.0` 起，四档记忆以每用户独立的 `users/<user>/improve/memory.sqlite3` 为唯一权威存储，旧式 Markdown 碎片、`data.json` 与 `storage.json` 不再参与读取，也不会自动导入。`filename` 保留 `.md` 后缀仅为稳定的逻辑身份与展示合同，不表示磁盘上存在对应文件。用户可以查看、纠正或删除记忆；临时重要热画像 `memory_temporary_important.md` 仍是可重建视图，不是权威数据库或第五个生命周期层。

::: danger 敏感信息
API Key、Token、密码、Cookie 和私钥不得写入长期记忆。运行时也会进行模式过滤，但不要依赖过滤器替代正确操作。
:::

临时重要记忆是由专门子代理维护的近期热画像。它引用已有临时记忆碎片形成可重建视图，数据流严格保持“用户对话原文 → 临时三层 → 临时重要热画像”的单向传递。后台整理和晋升临时三层时禁止读取热画像，防止反向加权；用户或主智能体主动查看时仍可只读访问，且查看不加权。被热画像引用的碎片不会在普通临时记忆段重复注入。任一来源失效、内容变化或重复时，系统会整体回退到全部临时记忆，等待下一次巡检重建。热画像文件不得删除、清空或写入空内容。

自动提取会把连续的待处理轮次组成批次，一次模型分析可产生多条候选，再统一匹配永久记忆、合并重复内容并批量落盘。相同批次带有稳定操作标识，失败重试不会重复创建或重复加权。

## 跨层搜索

`memory_manage` 的 `search_by_title`、`search_by_content` 和 `search_many` 支持传入 `tier: "all"`，一次检索 `seven_days`、`one_month`、`half_year`、`permanent` 四个记忆碎片层。每条结果都会返回真实 `tier` 和可精确定位的 `memory_ref`，后续可用具体层级读取完整正文。

`all` 只用于上述三个搜索动作，不适用于 `list`、`get`、新增、编辑或删除，也不包含由运行时维护的临时重要记忆热画像。需要列出某一整层时仍应使用具体层级的 `list`。
