# Web 界面使用

Web UI 是 React + TypeScript + Vite 构建的操作台，由 Python Web 服务提供 API。页面按真实工作过程组织，而不只是一个聊天框。

## 主要页面

| 路由 | 页面 | 主要用途 |
|---|---|---|
| `/chat` | 对话 | 流式对话、运行中追加引导、切换会话 |
| `/tasks` | 任务 | 管理任务计划与定时任务 |
| `/knowledge` | 知识 | 查看和维护分层知识 |
| `/memory` | 记忆 | 预览、纠正和删除记忆 |
| `/agents` | 子代理 | 查看当前用户可用子代理 |
| `/skills` | 技能 | 管理指令型技能 |
| `/sense` | 感知 | 查看、创建和刷新感知模块 |
| `/expand` | 拓展 | 查看与管理拓展模块 |
| `/files` | 文件 | 分页管理上传、智能体产物和临时文件 |
| `/messages` | 消息 | 查看外部消息插件和日志 |
| `/status` | 状态 | 查看服务与并发状态 |
| `/runtime` | 运行时 | 查看子代理、消息和拓展库存 |
| `/profile` | 资料 | 头像、用户人格和全局人格 |
| `/settings` | 设置 | 查看和修改受支持的配置、重启服务及检查版本 |

## 对话与运行中引导

聊天请求使用独立 `run_id`。运行中追加的引导进入专用队列，只会在 Provider 完成或工具调用结束后的安全边界注入，不会强行中断正在执行的网络请求或工具。

引导可以包含文本、图片、音频、视频和普通文件，也可以只发送附件。附件先上传到当前用户的 `file_upload`，再与本条引导一起提交；后端会重新确认用户归属、文件内容、媒体类型、大小和校验和。每条引导最多携带 20 个附件，不接受浏览器直接提交 URL、Base64 或任意本地路径。

Kemo 模式会依据当前模型的真实输入能力决定是否通过 Asset API 直接提供图片、音频、视频或文件。Chat 模式只沿既有视觉能力直接提供图片；没有被主模型直接接收的媒体仍保留为当前 Run 的受控资产，需要时由 `multimodal` 或 `file` 工具处理，不会因为不是图片而丢弃。

切换到其他页面不会切断正在进行的流式响应，返回对话页后会恢复当前运行现场。如果引导发送得太晚、工具循环已经结束，文本与全部附件会作为一个整体自动转入下一轮，而不是只保留文字。用户消息按纯文本展示，不进行 Markdown 渲染。

引导气泡会展示本次附件，并使用独立 `guidance_id` 确认生效状态，避免两条相同文本或纯附件引导互相匹配。完成后的引导归档在所属轮次的 Token 统计后方；历史重新加载时仍能看到附件元数据，源文件后来被清理则显示不可用状态。

点击停止后，停止请求与前端运行状态会保持同一轮次基线。停止过渡期间输入的文本会显示为“发送下一轮”，先进入下一轮队列；编辑重发后取消编辑也会保留撤销后的轮数基线，不需要刷新页面才能继续发送。

长对话首次只加载最近 20 轮；向上滚动时再分页加载更早记录。右侧用户消息导航最多显示 10 个刻度和 10 张轮次卡片，但它是跟随当前视口移动的动态窗口，不是固定截取最新 10 轮。悬停任意刻度时，对应轮次会旋转到滚轮 180°中心位，较早和较新的轮次按时间顺序排在上下两侧；滚动到最早已加载轮次或点击顶部加载入口时会继续请求上一页，并把新出现的旧轮次加入导航。

未发送的文字、已选择附件和上传提示按当前“用户 + 会话”保存在前端运行状态中。在 Web 内切换到记忆、文件或设置页再返回时会继续保留；刷新浏览器、关闭标签页或完整重启前端后不会保留，不能把它当作长期草稿箱。

浏览器会在 `localStorage` 中保存最近一次选择的内部用户名。再次打开未携带 `?user=` 参数的页面时优先恢复该用户；该记录只保存用户名，不包含 Web 登录 Token、密码或 Provider 密钥。

## 上传与粘贴

文件按钮和系统剪贴板都可以加入附件。在 Windows 复制截图、图片、压缩包或其他文件后，可以直接粘贴到输入框；附件可以不附带文字单独发送。单轮成功后，输入框上方的已上传提示会自动清除；模型服务失败或本轮未成功完成时保留本次附件，文本在模型服务失败时恢复，便于检查后重试。

单个普通上传文件上限为 80 MB，同名文件会自动增加序号以避免覆盖。发送时前端只提交受控的上传引用，后端会验证文件仍位于当前用户的 `file_upload` 目录，再按 Provider 类型和多模态路由转换；图片数据不会作为 Base64 长期写入文本历史。

已发送附件会显示在用户消息下方：图片显示缩略预览，其他类型显示文件卡片。仍位于 `file_upload` 的文件可以下载；用户后来清理源文件时，历史卡片不会消失，而会显示“源文件已清理”。

## 文件范围

Web 文件页只允许浏览、下载或删除 `file_upload`、`download` 和 `tmp` 中的普通文件；目录删除、路径穿越、符号链接、目录联接和隐藏缓存项会被拒绝。Windows 的 8.3 短路径与长路径别名会按文件系统身份识别，不会把同一个合法上传目录误判为越界。

三个区域都使用分页列表，每页默认显示 6 项，并支持路径导航和搜索。用户上传、智能体产物与临时文件都支持多选删除和全部删除；用户区域还支持重命名和下载，上传操作只允许写入当前用户的 `file_upload`。

文件为受支持的图片、音频或视频时，列表卡片可以直接预览或播放，也可以在独立浏览器标签页中打开预览。音频和视频使用浏览器原生进度控制。为避免预览占用过多内存和带宽，图片上限为 10 MB、音频上限为 100 MB、视频上限为 300 MB；超过对应上限仍可作为普通文件管理，但不提供媒体预览。预览接口继续执行用户目录、普通文件、扩展名、MIME 类型和符号链接边界校验。

技能页支持上传 ZIP 格式的用户自建技能。压缩包会安装到当前用户的 `user_skills/user_create/`，共享技能和内置技能不会被覆盖；具体结构和安全规则见[技能开发](/dev/skill-dev)。

知识页的层级概览卡片可以直接切换当前范围，知识文件以卡片化列表呈现并固定每页显示 10 个。这个分页数量只适用于知识文件；文件空间仍按每页 6 项加载。

消息页和系统任务状态页优先读取 `runtime/logs.sqlite3` 的结构化日志；旧 JSONL/Markdown 仅在数据库不可用或迁移失败时作为回退。

## 认证

Web 可以只启用 Token、只启用用户名密码，或者同时启用两种认证。同时启用时必须先验证 Token，再验证用户名和密码。Token 与密码通过登录请求体提交，不写入 URL、Cookie 或浏览器存储；浏览器只保存签名会话状态，完整登录默认保持 2 小时。

可以在 `.env` 中按客户端 IP 和认证阶段限制失败次数。部署在反向代理后时，只应把实际可信的代理 IP 或网段写入 `WEB_AUTH_TRUSTED_PROXIES`；未配置时服务不会采信转发头。

## 版本查看

设置页的“版本查看”会展示本地项目与四个组件的版本，并可连接 GitHub 检查云端正式版本。该功能只读取和比较版本信息，不下载文件、不修改代码，也不会直接执行更新。

发现新版本时，页面会提供适合当前系统的更新命令。进入项目根目录后执行：

```bash
python update.py --module all
```

Linux 环境如未提供 `python` 命令，可使用 `python3 update.py --module all`。更新完成后重启正在运行的服务。

::: tip 配置修改
设置页可以保存界面、Provider、上下文、权限和运行限制中受支持的结构化字段。已保存的 API Key 只显示脱敏占位，未修改时不会被覆盖；未在页面提供的高级字段仍需编辑对应配置文件。

当已保存配置使用 `kemo` 协议、网关鉴权有效且当前模型存在于模型目录时，思考强度选项由该
模型的能力声明动态生成；切换模型会切换到对应档位集合。模型不支持推理时选择器会禁用，能力
暂时无法刷新时页面会显示明确提示。`chat` 协议继续显示原有固定选择，不调用 Kemo 能力接口。
:::
