# v0.5.0 更新说明

`v0.5.0` 重点完善历史会话加载、上下文压缩、记忆后台任务和运行日志。升级前仍建议备份 `.env`、`users/` 以及自建模块；本版本不会删除旧的 JSONL/Markdown 审计日志。

## 历史与上下文

- 历史索引增加轻量归档指纹和快速定位路径。正常打开会话列表时不再反复解析每个大型 `data.json`，索引损坏或文件外部变化时仍会自动回退重建。
- 完整归档继续保存在 `users/<user>/history/<window>/`；Provider 使用的 `history/temp/<window>/` 仍是可裁剪的派生工作区，二者不会混淆。
- 手动上下文压缩现在会校验摘要缓存、临时工作区轮数、绝对轮次偏移、摘要覆盖范围和上下文快照。校验失败会回滚本次裁剪与摘要缓存，不会把“压缩成功”返回给网页端。
- 上下文摘要输入同时包含正文、reasoning/think、工具调用和关键工具结果；摘要输出预算上限提升为 20000 tokens，并要求非空、完整的结构化 JSON。摘要失败不会覆盖旧缓存。
- Provider 错误、取消和工具循环保护形成明确的失败/取消终态，失败轮次不会被静默删除，也不会给记忆加权或推进记忆提取。

## 记忆与后台任务

- 同一用户的 `background_serial` 子代理现在共享用户级串行锁，网页请求、Maintenance 和 Cron 不会同时修改同一用户的派生数据。
- 临时重要记忆热视图的来源失效、内容变化或重复时，系统会整体回退到临时记忆，不再注入不完整的热视图。
- 系统级记忆调度参数只从全局配置创建统一时间表，到期后按用户分别执行；用户之间的记忆和写入锁仍保持隔离。

## 结构化运行日志

- Cron 执行记录和外部消息路由记录新增 SQLite 存储：`runtime/logs.sqlite3`。
- 旧的 `cron/task_cron_system/log/*.jsonl` 和消息模块 `log/*.md` 仍作为兼容审计格式保留；首次读取按文件指纹幂等迁移，数据库不可用时网页会回退旧文件。
- SQLite 默认保留 90 天，可通过 `KEMO_LOG_RETENTION_DAYS` 修改；设置为 `0` 表示不自动清理。当前版本只清理结构化表，不自动删除旧 JSONL/Markdown。
- 日志只保存受限结果摘要、错误分类、附件路径和元数据，不保存附件二进制、完整提示词或 Provider 密钥。`runtime/` 已加入 Git 忽略。

## Web 与消息入口

- 停止运行、编辑重发、取消编辑和“运行中引导”共享同一轮次基线；停止期间输入的文本会排入下一轮，不会因前端状态过渡而静默丢失。
- Web 日志页优先读取结构化 SQLite，消息日志仍支持按平台和时间筛选。
- 关闭浏览器页面不会停止 RuntimeHost 托管的 Cron、消息路由或维护任务；只有停止 Python 进程或关闭后台宿主才会停止这些任务。

## 升级后检查

```bash
python update.py --module all
```

Linux 环境如未提供 `python` 命令，可使用：

```bash
python3 update.py --module all
```

更新完成后完整重启 kemo-agent，使新的运行时、调度器和日志存储模块生效。可以在设置页“版本查看”中检查本地版本和云端版本；该页面只检查版本，不直接执行更新。
