# v1.5.0 记忆证据链、上下文拆分与网页端主题落地

## 这一版在解决什么

v1.5.0 是一次以内部重构为主的主框架版本。长期记忆、上下文压缩、请求诊断与用量统计这几个体量偏大的模块被拆成职责单一的独立实现；记忆的生命周期也从「到期清扫」改成「可审计、可续跑、可归档」的流程。网页端在这一版完成 reference 主题落地与本机文档预览。版本面定为 `1.5.0`，`core`、`agents`、`plugins`、`web` 四个组件同步，配套网关基线仍是 `kemo-adapter-api 1.0.0` 与冻结的 Kemo 2.0 协议。

## 记忆：证据从哪里来，到期之后去哪里

此前记忆的加权只记录「哪一天加过分」，看得出次数，看不出依据。这一版把证据来源也记了下来，分成用户原文、助手叙述、手动审阅与历史迁移四类；同一天同时存在用户证据与助手证据时以用户证据为准，只有来源是用户原文的候选才允许被标记成「显式」——助手自己的叙述不再能把一条记忆顶成显式。旧数据缺少可信日期时按历史迁移登记，不反过来补造日期。

记忆到期后的处理也变了。旧版直接删除，这一版改为写入只写归档：内容留档，但永不进入提示词来源，也不参与检索。候选写入前会先做碎片尺寸校验，超出上限的候选直接拒绝，而不是先落盘再拆分。

提取过程改成了有界分页。模型提取按来源页推进、跨批次续跑，单次上限之外的条目会转入待办保留下来，不再被截断丢弃。自动生成的技能新增溯源文件，记录它来自哪几条记忆；记忆晋升发生结构性合并或拆分时，引用会跟着迁移，而普通编辑与删除不做迁移。技能与记忆之间的对账也改为非破坏式，删除技能只清理对应记录。

## 上下文、诊断与用量

上下文选择被拆成独立模块，整轮选择与 token、轮次两套下限分别处理；压缩收敛、轮次收尾与「请求内超限恢复」各自成为独立阶段，恢复过程不会重放已经完成的工具调用，也不会拆散工具消息组。运行窗口在进程内缓存缺失时按摘要覆盖的轮次做尾部重建，避免把已由摘要代表的归档前缀重新塞回上下文。

诊断侧新增请求指纹：只记录长度、摘要与结构信息，不保留正文，用于排查缓存命中率与跨轮一致性，运行诊断页会把这些脱敏证据同屏展示。配置新增 `agents.enable_mid_context_compression` 开关，默认关闭，统一控制逐轮摘要与旧工具结果缩略。

用量归一与任务级汇总迁到独立模块；会话注册表、窗口存储与提交边界进一步拆分；会话兜底扫描与记忆恢复任务收敛到调度模块。

## 网页端

网页端的消息日志改为按用户隔离，列表与计数都带用户过滤，消息页只显示当前用户的记录。新增本机 Office 转 PDF 预览：转换走本机 LibreOffice，不依赖任何云端文档服务，转换结果按用户与会话隔离，图片、音频与文档预览各自带独立上限。新增 Chat 模型发现接口，只使用服务端已保存的配置，不向浏览器暴露凭据，失败时保留用户草稿。任务中心新增「已完成清理」，先预览再执行，清理只隐藏视图，执行结果与诊断日志不删除；定时任务写入新增字段校验。

前端这一版落地 reference 主题：令牌、布局、组件、页面与生产别名桥接共七份样式接入统一变量链，页面与组件样式跟随主题令牌。交互上新增模型与思考档位选择、输入框自动高度与发送后回缩、当前会话文件弹层、会话导航与新建交接、重启后回跳、统一文档 Markdown 排版与只读预览；PDF 预览改为内置 pdfjs 资源，不再依赖外部 CDN。

## 验证

发布前检查八个阶段全部通过：版本一致性、开发期分层验收（92 项）、正式后端测试（1564 项通过、66 项跳过、348 项子测试）、模板合同（12 项）、编译检查、补丁格式、前端测试（66 个文件 / 589 项）与前端生产构建。推送之后，CI 与 Security 在 `main` 与 `v1.5.0` 标签上全部通过；期间暴露出一个只在 Windows runner 上出现的路径问题（临时目录的 8.3 短名与规范化长路径不一致），已在测试侧修正并复验。

## 关于分发

需要说明的是：**源码定档不等于各个分发渠道都已就绪。** 远程一键安装依赖本次 Release 的安装包与校验文件，npm 渠道依赖本次 Release 上传的分发包（版本名与固定名各一份），Docker 渠道依赖另行发布的镜像标签。本版已完成 Release 资产、npm 分发包与镜像标签的发布，三份内嵌包体（Release、npm、Docker 镜像内）的字节完全一致，匿名安装可用。

Release 安装包里已经包含构建好的网页端产物，目标机不需要再安装 Node 来打包前端。
