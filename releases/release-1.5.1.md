# v1.5.1 通用 Chat 兼容、知识分类数据表与用户骨架补齐

## 这一版在解决什么

v1.5.1 是一次以兼容性与数据组织为主的主框架版本。通用 Chat 兼容链路的请求净化、思考字段映射与 HTTP 传输从原先混在一起的协议适配里拆成独立模块；三层知识库的逻辑分类从文档层面的约定改成每个知识库目录内自带一张分类数据表。用户目录骨架、正文内联组件与页面样式、发布前验收与类型检查基座也在这一版收口。版本面定为 `1.5.1`，`core`、`agents`、`plugins`、`web` 四个组件同步，配套网关基线仍是 `kemo-adapter-api 1.0.0` 与冻结的 Kemo 2.0 协议。

## 通用 Chat 与 Kemo 线路的边界

Chat 兼容能力在入口负责把宽松输入洗净成符合协议的请求，这一点没有变。这一版把三件事拆开：请求字段净化、思考字段映射、HTTP 传输。思考侧现在支持字段别名、中转包装与带签名状态的工具续接；模型没有给出真实思考时使用带来源标识的兼容占位，占位不会被当作真实思考回传。DeepSeek 专用分支继续单独处理推理内容别名与中转站点特征。

Kemo 2.0 原生线路的请求与流式协议没有改动，协议校验的不变量也保持原样：需要放松约束时改 Chat 侧转换，而不是让协议为主流 Chat 实现放水。

## 三层知识库的逻辑分类

用户、共享、全局三层知识库各用一张分类数据表承载归类关系，支持新建分类、归类、移出与按来源筛选。同名分类按层级来源区分，归类操作不移动文档本身，文件路径保持稳定。

全局与共享层的默认分类表随源码仓库分发；从发布包安装的部署在首次读取时创建空表，需要的分类可在网页知识库里重新归类（发布包本身暂不携带默认表）。升级时仍保留部署者本机维护的分类数据，不覆盖本机数据。旧版本留下的 SQL 文本分类文件继续可迁移，解析改为按 SQLite 语法完整性切分脚本，只接受 classify 表的建表与插入语句——跨 Python 3.10 到 3.14 行为一致，安全边界不降低。

## 用户目录与骨架

用户目录骨架新增 `runtime` 与 `tools` 两类目录，模板显式声明并由创建器与自愈补齐逻辑为老用户兜底。补齐只创建缺失路径，不覆盖用户已有的配置、知识、记忆与文件。

## 页面的细节修正

任务计划气泡、独立认证页、知识库工具栏与全站选择控件的间距与主题令牌对齐；正文内联组件拆出基础件与轨道组件，消息日志按同一轮次展示输入与输出。跟进与引导消息、任务计划长标题与描述保留全文并支持内部滚动，输入坞辅助区按视口限高，多卡片同时展开或窄屏下仍保持发送框可见。

## 发布前检查

新增工作区类型检查配置，发布前验收扩为十一个阶段：版本一致性、仓库卫生、开发期分层系统验收、正式后端测试、模板合同、编译检查、类型检查、补丁格式、前端测试、前端生产构建与构建后分发产物隔离安装。前端构建产物进入 Release 包，目标机不必自行安装 Node。

推送过程中出现过两类只在 CI 才暴露的问题：一是知识库分类旧格式的迁移在 Python 3.10 上被 SQLite 授权回调拒绝，改用语句白名单后跨版本一致；二是 Windows runner 上会话切页延迟用例偶发超时，属于运行环境抖动，重跑即通过。两者都在发布前收敛，没有留到标签之后。

## 验证

发布前检查十一个阶段全部通过：后端测试 1641 项通过、68 项跳过、375 项子测试；模板合同 12 项；前端测试 68 个文件 / 605 项；前端生产构建与分发产物隔离安装通过。

推送之后，CI 与 Security 在 `main` 与 `v1.5.1` 标签上全部通过，包含 Python 3.10 与 3.13、Ubuntu 与 Windows 四个后端组合。Release 资产已上传：安装包、校验文件与两份 npm 分发包；匿名执行固定名 npm 安装成功，无需任何令牌。

三条渠道的字节一致：Release 安装包的 SHA-256 与 npm 分发包内嵌安装包、GHCR 镜像内 `/opt/kemo-release.zip` 的 SHA-256 完全相同（`289154fa8a40d89e1de6601c3d0d4f38dfea1314384a37665c63f275a6d0e65e`），镜像 `1.5.1` 与 `latest` 指向同一份内容。

## 已知边界

本地与 CI 检查通过不表示第三方模型、远程渠道或目标设备已经完成实机联调；升级前仍建议先在测试目录验证一次部署与启动。
