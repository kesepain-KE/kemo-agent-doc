# kemo-agent 1.2.5 — 删除栅栏、作用域隔离与发布前稳定性收口

1.2.0 让任务跑完为止，1.2.3 回答了「报错之后如何体面重试」，1.2.4 把外部智能体接进了调度链。1.2.5 是一次发布前的稳定性收口：它修复的不是「有没有功能」，而是并发、删除和作用域这三类一旦出错就很难察觉的问题——**历史删除后迟到的提交不再复活会话、任务计划不再越过对话空间、Windows 后台进程不再弹出终端窗口**。

同时，全局知识库从 24 个随版本累积的碎片文档重组为 7 个长期有效的专题文档，框架文档第一次拥有了稳定结构。

## 历史删除栅栏

此前存在一个窗口期：用户删除会话时，如果该会话仍有正在执行的 Run，迟到的终态提交会把已删除的会话和窗口原样写回数据库——删除操作被静默撤销。1.2.5 引入两层栅栏：

- **`history_deleted_sessions`**：删除会话/来源时先写入删除栅栏，迟到的终态提交检测到栅栏后拒绝重建会话、历史窗口或活跃绑定；
- **`history_deleted_windows`**：物理窗口墓碑（历史 schema v3→v5），已删除的窗口名一律拒绝后续写入，上下文摘要读写要求 runtime 窗口仍然存在，摘要 worker 迟到完成不再产生孤儿缓存；
- **`session_generation`**：每次会话预约携带代次标识；删除后同一逻辑 id 被新会话复用时，旧代次的 writer 全部被拒绝，防止旧 reservation 串入新会话。

配套修正：终态提交不再把已显式切换到新会话的 active 指针回退；窗口命名不再复用调用方传入的 `conv_*` id，避免两个来源恰好选择同一会话 id 时互相覆盖。栅栏只由显式的新预约清除，schema v3→v5 自动迁移，不丢既有数据。

## 子代理与任务计划的作用域隔离

1.2.0 已把任务计划按对话空间隔离，但子代理任务和若干 API 仍存在「缺省即通配」的缺口。1.2.5 把作用域变成硬约束：

- **子代理任务所有权**：`AgentTask` 携带 `source` / `session_id`；`get` / `wait` / `cancel` 对带作用域的任务强制匹配，缺失或不匹配一律视为任务不存在——一个会话无法探测、等待或取消另一个会话的子代理任务；
- **`subagent_dispatch` 插件**：`call` / `status` / `cancel` 强制要求 source + session_id；
- **任务计划插件**：`task_plan` 的活跃计划查找在缺失作用域时不再视为通配，一律拒绝；
- **Web 任务 API 全面作用域化**：任务列表、创建、更新、编辑、重试、修订、回滚、暂停/取消、删除全部携带 `source` + `session_id`，服务端逐项校验会话归属；运行中引导与 Run 取消同样要求会话身份；
- **计划修订脱敏升级**：revision 快照中的敏感键匹配从精确拼写扩展到 camelCase 归一化与凭证形态识别（Bearer 头、sk- 前缀、PEM 私钥块），浏览器侧看到的修订视图始终是脱敏投影。

## App 桥接恢复与事件边界

- **run_id 别名**：长任务续跑产生新 run_id 后，旧 run_id 自动注册为规范 id 的别名，App 端恢复、流式订阅与取消在续跑前后保持连续；
- **会话强制校验**：快照、流式、取消、引导、任务计划、状态接口强制要求 `session_id` 且与 Run 归属一致，不一致返回 404；仅凭 `client_id` 即可查询本设备全部活动运行；
- **事件订阅 fail-closed**：未携带会话的对话/任务事件不再升级为用户级广播，事件只会送达真正属于该会话的设备。

## Windows 进程默认无控制台

框架启动的插件隔离进程、拓展/感知子进程与后台 Shell 此前可能在桌面弹出黑色终端窗口。1.2.5 起这些进程默认以无控制台方式运行：spawn worker 优先使用 `pythonw.exe`，无控制台 worker 自动补齐安全的 discard 流。需要临时观察输出时，Shell 单次调用显式传入 `show_terminal=true` 即可创建可见控制台——只影响这一次调用，不写入会话或配置。

## Web 前端：重试快照与会话级运行状态

- **重试边界可视化**：Provider 输出异常触发自动重试时，失败尝试不再直接消失——前端将其封存为快照（流式文本冻结、执行中的工具标记为带说明的错误态），随后以「第 N 次尝试继续执行」的边界横条开启新尝试，重试过程第一次变得可读；
- **运行状态按会话解析**：`chatRunning` / runId / 中止控制器从全局单例改为按 `(user, session)` 键控的多实例状态，切换会话时不再看到别的会话的「停止生成」按钮，路由切换瞬间的状态串扰被消除；不同会话可以真正并行运行各自的对话；
- **引导预览与长任务横条**的溢出与边角细节修正（`box-sizing`、最大高度、滚动条）。

## on_commit 记忆提取修复

真实运行的 `on_commit` 记忆提取此前因参数合同缺失而静默无法产出候选：分析管线现在把 `agent_source` 与 `session_id` 一并透传给 `self_improve`，逐轮提取恢复正常。

## 全局知识库重组

24 个随版本累积的旧文档归并为 7 个长期专题：内置拓展、配置参考、知识与用户数据、模块开发、Provider 可靠性、存储与持久化、任务自动化。删除了 `release-1.2.x-stability` 系列等「版本快照型」文档，所有交叉引用同步更新、无残留断链。此后文档不再随版本膨胀，只在专题内演进。

## 兼容性

- 历史 schema v3→v5 由启动迁移自动完成，不丢既有数据；
- 带作用域的子代理任务无法通过旧的无作用域 API 读取或取消；无作用域的遗留任务仍可由可信内部调用方使用；
- `show_terminal=true` 仅影响单次 Shell 调用；
- App 桥接版本同步至 v1.1.6，旧客户端的 run_id 在续跑后仍然有效。

## 验证

发布前完整验收通过：test_kemo 90 项、正式 Python 测试 1047 项（含 6 项跳过与 67 组子测试）、模块模板合同 10 项、全量编译检查、前端 Vitest 232 项（29 个文件）、TypeScript 与 Vite 生产构建。新增回归覆盖历史删除栅栏、知识库链接拒绝、子代理作用域隔离、App run_id 别名恢复与重试快照渲染。
