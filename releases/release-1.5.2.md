# v1.5.2 子代理协作、媒体装载与网页工作面板

## 这一版在解决什么

v1.5.2 是以协作与可观察性为主的主框架版本。这一版把子智能体从「同步等待一次交付」推进到可预算、可停止、可续跑、可指导的协作对象，并把它真正用起来：新增通用执行助手 `general_worker` 承接重复性工作，子任务默认后台提交、并行推进，主任务按必要依赖收口。同一版里，工具取得的媒体可以装载到下一次原生模型请求，网页增加右侧多标签工作面板观察后台作业与子任务详情，上下文压缩收敛成「先轮数、再 Token」的统一管线。版本面定为 `1.5.2`，`core`、`agents`、`plugins`、`web` 四个组件同步，配套网关基线仍是 `kemo-adapter-api 1.0.0` 与冻结的 Kemo 2.0 协议。

## 子智能体协作

子任务默认只向主智能体交付结论、必要证据、产物和未完成事项，不再回灌工具轨迹；完整执行过程留在执行记录与网页详情里，不进入主模型上下文。

工具额度与运行时长改为按段计算。主智能体可指定每段工具额度（0 表示不限次数）和本段运行时长，额度耗尽后保留现场、结论与累计用量，原任务可显式续跑并获得新段额度。只有真实退出且可恢复的任务才允许续跑，仍在停止中的线程不会被声明已退出，执行槽、锁与主任务完成屏障不提前释放。

普通公开本地非串行 LLM 子代理的调用默认后台提交，多个独立调用能在第一个完成前全部提交；显式同步、特殊规划、串行维护与外部代理仍按各自合同执行。等待与执行按安装根、用户、来源与会话公平派发，同一空间多窗口不重复配额，空闲执行容量可以借用，新空间的首次入队位置受保护。

新增内置子代理 `general_worker` 在当前用户授权范围内承接文件处理、脚本、检索整理、批量操作与测试验证，禁止再次委派，不自动继承主历史，拓展与感知按需使用。

## 媒体装载

新增 `attach_media` 插件：工具取得的图片、音频、视频或文档可登记到当前 Run 的下一次主模型请求，由主模型原生接收。装载意图与队列状态跨进程隔离并按 Run 去重，工具成功、网页预览与模型实际收到分别记录，不混为「已看过」。

媒体装载与委托专用模型的 `multimodal` 是两个不同入口。Chat 侧原生图片上限保持 20 MiB 且不静默压缩，Kemo 线路按 1 MiB 内联边界执行，超出走 Asset。Chat 的原生图片能力由框架按内置厂商档案自动选择，用户不必自行检测；未知高级媒体能力继续 fail-closed。

## 网页工作面板与界面

右侧新增多标签工作面板，支持文件预览、当前对话空间的后台 Shell 作业与子代理详情，默认提供草稿本。终端以独立卡片展示任务归属、完成时间与耗时，关闭标签不会取消任务。子任务按主任务分组展示，工具参数与返回结果可展开，回复渲染在独立正文容器里。

运行状态面板展示真实 API 请求池占用与当前对话空间的 Token 缓存命中率。历史对话支持置顶、收藏和右键操作，全部删除覆盖只读来源。主题页提供九种语言与用户背景的图片或视频设置，UI 透明度和毛玻璃可调，背景图片上限 100 MB、视频 400 MB。网页认证改为两阶段布局，输入坞的跟进与引导消息、任务计划长文本保留全文并支持内部滚动。

## 上下文与运行安全

手动压缩、轮数达到上限、本地 Token 达到上限、API 实际输入用量达到上限、以及 API 明确返回上下文超限，统一进入同一条管线：先按轮数整理并重新判断，整理后仍超限才进入 Token 阶段，且至少保留一个完整对话轮次。API 实际输入用量支持轮末与跨轮校准，摘要请求有独立完整预算，超大单轮内部安全分片，失败保留原历史与旧摘要。

宿主控制与资源异常不进入业务重试，也不变成普通业务错误；同步与 async 工具入口共用同一桥接，处理事件循环归属与取消边界。复用策略在主智能体与子智能体之间统一：动态读取实时刷新，已成功的副作用按签名防重。

Web SSE 增加静默期注释心跳并按配置返回实际间隔，保持单个 pending next；断开、取消与响应发送失败都会释放并发槽，但不伪造线程结束。SQLite 结构变更先备份再事务提交，版本戳与 DDL 同事务，更新前对用户库整库备份。后台 Shell 结束后向所属智能体交付可确认的短通知，只含状态、时间、退出码与有界五行尾部，完整日志仍按需查询。

## 校验与分发

发布前检查扩展为十二个阶段，新增常驻手册契约与版本一致性检查：手册结构、关键来源路径与内置能力可达性参与验收，开发期 `test_kemo`、正式 Python 测试、模板合同、编译与类型检查、前端测试与构建、构建后分发产物隔离安装共同防止旧构建与缺失模块进入交付。前端构建产物进入 Release 包，目标机不必自行安装 Node。

手册契约的源码指纹改为先归一化 AST 形状再取哈希：`ast.dump` 在 Python 3.13 起省略空列表字段、3.12 起为函数增加 `type_params`，同一份源码在 3.10 与 3.13 会得到不同指纹，会误报源码行为变化。

## 升级与兼容说明

源码更新器与部署更新器的两层边界不变：源码更新按 core、agents、plugins、web 四个板块推进，部署更新以整份 Release 为单位。历史数据库 schema 升到 7，采用备份后事务迁移。Kemo 2.0 协议与 `kemo-adapter-api 1.0.0` 兼容基线没有变化，DeepSeek 专用适配保留。

子代理任务账本用 `psutil` 核对执行进程的创建时间，本版把 `psutil` 明确加入核心依赖清单；此前它只是本机已装而未声明，干净环境安装后会因缺少依赖无法登记主任务。

Python 3.10 的取消语义与 3.11 起不同：3.10 没有 `Task.uncancel()`，anyio 的 asyncio 后端无法把外部取消与本 scope 的取消区分开。因此在该版本上，靠取消 Task 模拟的断开不会立即中断请求，真实客户端断开仍由 `is_disconnected()` 探测负责；相关断言按解释器版本区分，资源释放必须恰好一次的约束在两者上一致。
