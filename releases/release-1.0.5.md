# kemo-agent 1.0.5 — 注入三态与连续性加固：把数据流向的决定权交还给用户

1.0.3 回答的是"模型看到的感知与拓展数据越来越旧怎么办"，答案是动态段一次逻辑请求一刷新；1.0.5 接着回答下一个问题——**"实时刷新"是所有人都需要的吗**。

实时刷新确实让工具续轮、运行中引导和上下文恢复都看到最新快照，但它也有代价：每一轮对话里每次模型请求都要重读磁盘、重拼动态段，系统提示词的前缀不再稳定，Prompt Cache 的命中率也随之下降。对经常跑长工具链的用户这是值得的；对普通问答为主的用户，这可能只是白白增加开销。

1.0.5 没有替用户做这个决定，而是把决定权交还给用户：**拓展与感知各自拥有独立的用户级总闸门与实时开关，形成「不注入 / 按轮注入 / 实时注入」三态**。同一份数据，可以完全不给模型看，可以一轮固定一份快照，也可以每次都取最新。

这一版同时合并发布了此前积累的连续性增强：Provider 工具参数异常自动恢复、Web 跨渠道只读历史、生成媒体校验和找回，以及两处前端布局修复。

---

## 三态注入策略

新配置位于用户配置的 `expand` 与 `perception` 段，两组开关彼此独立：

| 配置 | 默认值 | 含义 |
|------|--------|------|
| `expand.prompt_injection` | `true` | 拓展数据总闸门。`false` 时整个 `[expand_data]` 段不进入系统提示词 |
| `expand.realtime_injection` | `false` | `true` 时每次逻辑 Provider 请求前重读最新拓展快照 |
| `perception.prompt_injection` | `true` | 感知数据总闸门。`false` 时整个 `[perception]` 段不进入系统提示词 |
| `perception.realtime_injection` | `false` | `true` 时每次逻辑 Provider 请求前重读最新感知快照 |

三态行为：

- **不注入**：总闸门关闭，对应 Prompt 段被完整省略。后台采集、主动调用拓展、感知采集**全部不受影响**——数据照常入库，只是不进系统提示词。
- **按轮注入**（默认）：本轮对话开始时读取一次固定快照。提示词前缀稳定，Prompt Cache 命中率最高。
- **实时注入**：每轮内的工具续轮、运行中引导续轮、上下文超限重试都重读后台采集器已发布的最新快照。

配套的用户界面：

- Web 设置页「来源白名单」区新增四个开关：拓展数据注入、拓展数据实时注入、感知数据注入、感知数据实时注入；总闸门关闭时实时开关自动禁用。
- 上下文窗口抽屉顶部新增「数据注入策略」只读气泡，实时展示当前生效模式，帮助你在实时感知能力与 Prompt Cache 命中率之间做出明确取舍。
- 运行状态与 Prompt 分段诊断把关闭状态统一报告为 `disabled`，不再把「不注入」误记成「空段」或「已注入」。

## 工具参数异常自动恢复

模型偶发生成不完整的工具参数（arguments 不是完整 JSON 对象）时，旧版本只能把这轮记为失败。1.0.5 在**确认没有副作用**的前提下可以自动恢复：

- 触发条件：统一终态为 `invalid_tool_arguments`，且该次尝试尚未发布文本、思考、媒体或完整工具调用——也就是说还没有任何可见输出，也**没有执行过任何工具**。
- 恢复方式：用新的 `request_id` 发起一次新的逻辑请求，在系统消息中临时加入「只重新生成完整工具调用」的纠错指令；纠错指令不写进持久化对话历史。
- 次数上限：`tools.invalid_tool_arguments_retries`，默认 2，`0` 表示禁用。
- 边界保证：失败尝试不会进入对话正文或工具卡片；但已经产生的 Provider Usage 会计入本轮统计。一旦已有可见输出、完整调用或达到上限，就保持明确失败终态，绝不静默重放可能有副作用的工作。

## Web 跨渠道只读历史

Web 历史列表此前只显示 Web 自己的会话。1.0.5 起按当前用户统一读取全部来源：**Web、CLI 与外部消息（`message:<platform>`）** 的归档都出现在历史抽屉里，并标注来源。

- Web 会话仍可切换、删除、重试摘要；
- CLI 与外部消息会话在网页中**只读查看**——点击后打开只读归档对话框，可以分页浏览正文、摘要与来源信息，但网页不会接管、续写或修改这些会话；
- 会话卡片新增完整记忆处理状态：记忆状态、已处理轮次 / 目标轮次、排队原因与最近失败信息；
- 分页游标升级为 `[updated_at, session_id, source]` 三元素，时间戳相同的会话不会漏项或重复。

记忆仍然按用户共享：所有入口绑定到同一内部用户后共用同一个 `memory.sqlite3`，记忆页不按渠道过滤。

## 生成媒体校验和找回

生成图片、音频等媒体产物此前按相对路径引用，文件一旦移动到下载区的嵌套目录，链接就失效。1.0.5 新增按内容找回：

- 新端点 `GET /api/users/{user}/artifacts/{checksum}`：按 **SHA-256 + 文件大小** 定位产物，不依赖路径；
- 解析器使用有界 LRU 缓存（256 条）、5 秒负缓存与受限递归扫盘（文件 20000 / 哈希候选 128 上限），异常链接不会反复触发无界扫盘；
- 响应使用长期缓存头与 CSP / nosniff 安全头，拒绝符号链接与路径穿越；
- 前端媒体卡片优先使用校验和 URL，路径失效时自动回退到下载区路径。

## 前端修复与 CI 加固

- 技能编辑器：Markdown 文档区域高度与滚动修复，不再出现编辑器与预览互相挤压；
- 超长引导气泡：内容支持横向滚动，不再撑破布局；
- 发布检查器 `check_versions.py` 新增全局知识文档版本一致性校验，`project-introduction.md` 与 `version-and-update-modules.md` 必须与根版本一致，防止文档与版本号脱节。

## 从 1.0.3 到 1.0.5

| 维度 | 1.0.3 | 1.0.5 |
|------|-------|-------|
| 动态段生命周期 | 固定实时刷新 | 用户三态：不注入 / 按轮固定 / 实时刷新 |
| 控制面 | 无（框架统一） | 用户配置 + Web 设置页开关 + 上下文只读气泡 |
| 工具参数损坏 | 整轮失败 | 无副作用时自动恢复（默认重试 2 次） |
| Web 历史 | 仅 Web 会话 | Web / CLI / 外部消息统一展示，非 Web 只读 |
| 媒体产物引用 | 相对路径，移动后失效 | SHA-256 + 大小找回，路径变化仍可下载 |
| 关闭状态诊断 | 记为空段 | 明确报告 `disabled` |

## 开始使用

```bash
cd kemo-agent
git pull
python update.py --module all
```

更新完成后，请完整重启 kemo-agent，使新的 Python 运行时与 Web 前端构建一起生效。

::: tip 升级提示
1.0.5 的默认注入模式是**按轮固定快照**（`realtime_injection` 默认 `false`）。如果你习惯 1.0.3 的实时刷新行为，请在用户配置或 Web 设置页中开启对应数据源的实时注入：

```json
{
  "expand": { "realtime_injection": true },
  "perception": { "realtime_injection": true }
}
```

新增配置项：`tools.invalid_tool_arguments_retries`（全局，默认 2）。不配置也可用默认值；`0` 可关闭工具参数自动恢复。
:::

## 写在最后

1.0.3 解决了"数据太旧"，1.0.5 解决了"谁来决定多新才算合适"。

这两版合起来是一个完整的故事：**框架负责把数据流真正动起来，用户负责决定数据以什么节奏进入模型**。实时刷新不是默认，而是选项；不注入也不是隐藏，而是闸门。采集照常跑，调用照常通，区别只在于模型每一轮看到什么——现在这件事由你说了算。

与此同时，工具参数损坏不再让整轮白费，跨渠道的对话终于能在网页里被完整看见，移动过的生成媒体也总能被找回来。智能体在长链路里越走越稳，就是这一版想说的话。
