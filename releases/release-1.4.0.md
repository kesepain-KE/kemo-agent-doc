# v1.4.0 三仓协议对齐、正文组件扩展与工具报错脱敏

## 这一版在解决什么

v1.4.0 是一次跨项目的版本对齐。kemo-agent 主框架升级到 `1.4.0`，配套的 Kemo 网关升级到 `1.0.0`（对应 Kemo 2.0 线路协议），知识图谱项目升级到 `1.6.0`。三个项目现在用同一份协议合同说话，版本之间不再错位。

围绕这条主线，这一版把四件事做完了：把协议里一直没补全的部分补齐、让工具参数出错的提示不再泄露原始内容、让 Kemo 协议与 Chat 兼容协议各归其位、并显著扩展了回复正文里的内联组件。

## 协议补齐

此前协议里有些字段只做了粗略检查，这一版把它们补全并收敛。最直接的变化是各类标识符现在有明确的前缀要求——消息、推理、工具调用与工具结果各用各的前缀，请求、响应与资产也是如此，长度与字符集一并受限。好处是拼装错误会在最早的地方被发现，而不是等到后面某一步才表现成难以定位的故障。

同时补齐的还有向量化（Embedding）、重排（Rerank）、批量响应与结构化输出等类型，并新增了一批请求级校验：工具调用与工具结果必须一一对应、名称必须一致、重复结果会被拒绝。流式事件的顺序与结束方式也做了对齐。

这些约定不再只写在代码里：项目新增了一份外置的协议规格与一组正例、反例样例，让协议合同可以按数据来描述与核对。

## 工具参数出错时不再回显原文

如果模型返回的工具参数格式不对，旧版会把原始参数一并放进错误信息里，方便排查——但这也意味着参数里一旦含有密钥之类的内容，就会跟着错误进入日志和界面。

这一版改为只保留长度、是否被省略、错误摘要等结构化信息，原始文本不再外泄。排查能力通过长度与省略标记保留下来。

## Kemo 协议与 Chat 兼容各归其位

Kemo 原生协议与 Chat 兼容协议的关系在这一版里更清晰：兼容层负责在入口把第三方的宽松输入整理成合规形状（统一标识符、去重、补字段），协议本身不为迁就 Chat 而放松要求。两条链路各有独立的传输重试预算，互不影响。

## 正文内联组件扩展

回复正文里的内联组件这一版扩充了不少。除了原有的卡片、图表、表格、表单与建议追问之外，新增了组合布局、位置示意、影音、文件、商品、订单、投票与评分等组件；底层还内置了卡片、列表、行列、Markdown、图标、按钮、日期、选择、输入、滑杆与开关等常用积木。写得出来的东西更多了，未知组件仍然会安全地降级成通用数据卡。

## 模块创建更安全，结构更清楚

模块创建器（拓展、感知、技能）新增了一处共用的安全检查，路径与字段校验统一在一处完成，仍然保持「先全部校验、再原子发布」——创建失败不会留下半个模块。

结构方面继续按低耦合、高内聚拆分：历史模块拆出了会话载荷序列化，任务模块拆出了执行支撑，Web 后端拆出了对话闸门、媒体支撑与设置解析。对外入口和行为保持不变。依赖上新增 `jsonschema`，用于协议规格的校验。

## 验证

这一版进过完整的发布前检查，八个阶段全部通过：版本一致性、开发期分层验收（92 项）、正式后端测试（1443 项通过、66 项跳过、235 项子测试）、模板合同（12 项）、编译检查、补丁格式、前端测试（45 个文件 / 383 项）与前端生产构建。Kemo 网关与知识图谱两侧的协议合同测试同步通过。

## 关于分发

需要说明的是：**源码定档不等于各个分发渠道都已就绪。** 远程一键安装依赖本次 Release 的安装包与校验文件，npm 渠道依赖本次 Release 上传的分发包（已上传，匿名安装可用），Docker 渠道依赖已发布的镜像标签。本版已完成 Release 资产与 npm 分发包的上传。

Release 安装包里已经包含构建好的网页端产物，目标机不需要再安装 Node 来打包前端。
