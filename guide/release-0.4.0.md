# v0.4.0 更新说明

`v0.4.0` 重点完善长对话、历史摘要、多模态输入、拓展操控和文件编辑的可靠性。升级前请按[安装部署](/guide/installation#更新)中的说明备份 `.env`、`users/` 和自建模块。

## Web 对话

- 未发送的文字、附件卡片和上传状态按“用户 + 会话”保留；在 Web 单页应用内切换页面再返回时不会丢失。刷新浏览器或关闭页面仍会清空未发送草稿。
- 已发送附件会作为对话内容显示。图片保留预览，普通文件显示文件卡片；源文件被清理后卡片仍保留，但会标记为不可用。
- 第一轮编辑重发不再回到欢迎页；撤销后的历史轮数会与后端重新对齐。
- 最近一次选择的用户保存在浏览器本地存储中。重新打开没有指定 `?user=` 的页面时，会优先恢复该用户；用户已删除时回退到当前用户列表首项。
- 已完成或失败的任务计划会归档到对应对话轮次，不再长期悬浮在输入框上方。
- 历史卡片的省略摘要支持悬停查看完整内容，悬浮层不会被抽屉滚动区域裁剪。

## 对话、历史和摘要

- Provider 错误、拥塞、事件流缺少终态或上下文恢复失败时，本轮已有进度会以 `failed` 终态写入历史；下一条用户消息自然进入下一轮。失败轮次不进入记忆提取，也不会给记忆加权。
- 只发送附件的轮次会持久化安全的附件引用，下一轮重建上下文时不再生成空 `MessageItem`。
- 手动上下文压缩增加一次严格 JSON 修复重试，并提高长摘要的分块预算。
- 历史标题与摘要优先通过结构化输出工具提交；非标准 JSON 可尝试恢复，最终仍失败时生成安全的本地兜底标题和摘要。
- 历史搜索读取完整归档正文，并使用归档创建时间按北京时间过滤，不再依赖新式随机目录名是否包含日期。

## 多模态

- 专用多模态工具接受当前 Run 资产、项目相对路径和已经确认过的绝对路径。
- 图片在调用模型前会完整解码验证。Chat 图片通道接受 JPEG、PNG、WEBP 和 GIF；不支持的格式会给出明确转换提示。
- 图片分析、音频转写和视频分析遇到可重试的瞬时上游错误时最多自动补试一次；生成和编辑类操作不会自动重试，避免重复计费或重复产物。
- 多模态专用调用的最大输出预算提升为 10000 Token。该值是总输出预算，具体模型仍可能把较多预算用于推理而没有正文。

## 拓展和文件工具

- 新增 `expand_call` 工具。拓展操控通过结构化 stdin 在隔离子进程中调用 `execute(command, params)`，不再要求主智能体通过 Shell 拼接参数。
- 拓展采集可以返回资源索引，操控可以返回文件产物；框架校验产物后发布到当前用户的下载空间，并在 `_runtime.json` 记录最近采集和操控状态。
- 感知、拓展、消息平台、技能和子代理目录只规定框架入口，不限制内部工程布局。模块可以保持单文件，也可以包含完整项目。
- 文件编辑新增原文/哈希并发保护、显式整行删除模式、不覆盖的编号备份、编辑前后哈希和带行号预览，降低行号偏移、Tab 和换行差异造成的误写风险。

## 更新命令

```bash
python update.py --module all
```

Linux 系统没有 `python` 命令时使用：

```bash
python3 update.py --module all
```

更新成功后应完整重启 kemo-agent。只重启 Web 页面不会让已运行的 Python 进程重新加载核心代码。
